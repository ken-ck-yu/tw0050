- **Decisions I had to make:**
  1. Eras (tpex.otc three eras, twse.mi_index, twse.mi_qfiis) were not in `schema.py`; registered lazily in `run()` via `ensure_eras()` only if `schema.ERAS` has no entry for the endpoint (no import-time global side effect, no duplicates if the Lead adds them). mi_qfiis era has no first date (only a 2022 sample exists); mi_index first date 2015-03-02.
  2. Cache flush happens before the clean append (raw survives a crash), then state is marked; the spec lists append first.
  3. A no-trade row with null prices stores 0 for empty volume cells; an empty volume cell on a row with prices is `ParseError`. TWSE rows with `--` prices but non-zero volume (e.g. 1418 on 2016-06-01) keep their volume values.
  4. A shares row with an empty `發行股數` is skipped rather than failing.
  5. Discrepancy days (pair both empty) are marked done in state and no `mi_qfiis` request is made.
  6. `calendar_diff.json` carries `dataset`, `key_type`, `completed` keys: `cli status` reads every `data/state/*.json` with `e["completed"]` and would crash on a plain diff document.
  7. market_cap: one DuckDB query per month, derived table recomputed every run (no state), raises `KeyUniquenessError` if a stock id sits on two markets on one date. Returns quietly when prices or shares have no files yet.
  8. Snapshots: stopgap import groups all new files per name into one append, de-duplicates equal keys keeping the earliest fetch, and records imported files in state dataset `snapshots_stopgap`. Unknown names in the manifest are skipped with a warning; a sha256 mismatch or non-list payload is `DriftError`. `snapshot_date` is the Taipei date of `fetched_at`, ignoring any date in the body (per Lead).
- **What in my instructions was missing, ambiguous or wrong:**
  - The spec called for `ctx.twse.openapi(path)`, which originally served from the cache (identical daily request); the Lead fixed it in main and I use it as written.
  - M0 section 7 says `snapshot_date` comes from the body when present; A-1 spec says fetch date. Followed A-1 and the Lead's confirmation.
  - `status` crashes on any state-dir JSON without state keys (see decision 6); state files for non-date datasets are under-specified.
  - `listing_status` columns were not named in the spec text (used `market, stock_id, first_date, last_date`).
  - The spec says `mark_dates` per batch but not what range; I mark `[first, last]` of the batch's pending days (done and non-trading days inside the range are harmless).
  - The ERAS registration owner was conditional ("if missing, register them") and the 2020 and 2025 TPEx boundaries come from the spec text, not from observation.
  - `snapshot_<name>` empty payloads: state is per-table `snapshot_<name>` (date range of the Taipei day).
- **What I would do differently next time:** write the shared test helper into a shared owned location agreed with A-2 up front (I used `tests/agent_a/a1_helpers.py` with a `sys.path` insert plus `noqa: E402`, because there is no `conftest.py` I may own without colliding with A-2).
