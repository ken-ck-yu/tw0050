Key collisions in the fixtures: 0 (only the synthetic collision test and repeated yearly windows produce any). `adjusted.UNCOMPUTABLE_EVENTS` is 0 on the fixtures.
- **Decisions I had to make:**
  1. `權息` and `除權息` map to `ex_rights` (as the spec says); TPEx cells `除權`/`除息` accepted too, since ex_daily uses those forms.
  2. TWT49U cash and stock dividend columns are null (only the sum `權值+息值` exists).
  3. Collisions keep the first row in response order (Lead update).
  4. `as_of=None` means every event counts and `is_ex_date_window` is false; a null `available_at` is treated as pending (excluded when `as_of` is given, window true).
  5. Raw price rows are not filtered by their own `available_at` (spec silent); optional `only_available_prices=True` does it.
  6. Uncomputable factors give 1.0 and a counter (Lead update); `split`/`par_value_change` use exactly `1/ratio` (Lead update).
  7. `available_at` is null when the calendar does not reach the next trading day (pending, fill later).
  8. The manual path is the module variable `MANUAL_PATH` (tests point it at a fixture); default `config/manual_corporate_actions.yaml`.
  9. Missing feed fields raise `DriftError`; a missing TAIEX_TR or TAIWAN50_TR row raises `DriftError`.
  10. price_limits: TPEx event date is `next_trading_day(file date)`; the sentinel null rule is applied to the TWSE side too (9999.95 up, 0.01 down), a `limit_down` above `limit_up` raises `SanityError`; state is marked per trading day for TWSE and the TPEx file of that day together.
  11. benchmark state marks days for the TWSE part only; TPEX_TR is re-requested each run (cache-first, one FinMind call per calendar year).
  12. The registered view is `adjusted_close` (as_of infinity), created by `register_views` when both source tables have files.
- **Problems hit and how each was resolved:** an early version raised on uncomputable factors, replaced per the Lead update. A DuckDB connection error from running two statements without finishing the first result, fixed by fetching the count fully. Several test fixtures return the same body for each yearly window, so collisions appear in multi-year tests (asserted).
- **What in my instructions was missing, ambiguous or wrong:** the spec's "Adjusted prices" design text says capital reduction uses `reference_price / halt_close`, while the spec says `prev_close` (the two are equal for reductions). M0 section 5 names the view `adjusted_as_of`, the spec `adjusted_close`. The spec says the TPEx `price_limits` come from "the previous trading day's file stored on the next day", which leaves the first window day without TPEx rows; this was settled by the Lead update. `ctx.cache.get` returns `fetched_at` None for some fakes, so modules fall back to the current time. The spec lists `權息` but the TWSE fixture only contains `權` and `息`. The Lead's `Response.fetched_at` on a cache hit is the stored time, good. TWT49U event dates use `114年01月02日` which `roc_to_date` handles. The ex-ante fixture for revivt needs a 7-digit date; confirmed `恢復買賣日期` (spec says "confirm from the fixture").
- **What I would do differently next time:** merge main before coding to pick up the Lead's updates earlier.
