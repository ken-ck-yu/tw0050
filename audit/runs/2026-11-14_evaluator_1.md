- **Files created or changed:** `src/twdata/research/__init__.py`; `src/twdata/research/evaluator/{__init__,constants,data,costs,engine,metrics,log}.py`; `tests/research/evaluator/{conftest,helpers,world,test_costs_metrics,test_engine,test_data_log_frozen,test_frozen}.py`; `docs/data_dictionary/research_evaluator.md`; `research/EVALUATOR_SHA256`; this report. Nothing else.
- **Result:** offline only, no data collected. 35 evaluator tests (195 in the whole suite) pass, all synthetic Parquet in temporary directories.
- **Problems hit and how each was resolved:** none blocking. Ruff import ordering in tests (sibling helper modules treated as first party) was fixed with `--fix`.
- **What in my instructions was missing, ambiguous or wrong, and the decisions made** (conservative option chosen where there was a choice):
  1. *Turnover definition.* "Sum of one-way traded notional per year" can mean buys plus sells or half of that. `annual_turnover` = buys plus sells (two-sided, the larger number); `annual_turnover_one_way` is the half. H1's "40% to 60% one-way a month" should be compared with the one-way field. Each trade is divided by NAV at that day's open.
  2. *Cost drag* = sum of costs over NAV at the open of the fill day, per year. Final liquidation costs are included in turnover, drag and returns (the benchmark treats its exit the same way).
  3. *Deflated Sharpe details.* "0.5 times the observed Sharpe" read as the standard deviation of trial Sharpes (variance `(0.5 SR)^2`). Trial Sharpes use the logged `ok` runs plus this run, converted to daily units; N=1 gives SR0 = 0; N=2 uses the fallback; N>=3 needs at least two logged Sharpes, else the fallback. Skewness and kurtosis are population moments (raw kurtosis), as the formula needs.
  4. *`n_trials`* counts every log row (error rows included), all cycles, as the spec says. The *budget* counts rows with `cycle == settings.research.cycle`, error rows included (a failed run uses a run). A refused 11th call writes nothing; the spec did not say whether it should be logged.
  5. *Window and data range.* The spec names `window` without defining values. Allowed: `train`, `validation`, `dev` with the dates in the spec; a book whose decision date is outside the window raises `BookError`. The series ends with a forced liquidation at the open of the last trading day at or before `min(data.end, window_end)` (the spec did not say how the window ends). Limit locks are not applied to this final liquidation.
  6. *Tradeable mask.* Added a condition the spec does not list: a missing adjusted open on E also drops the target (the return cannot be computed). The mask gates buys; a held name that is no longer targeted is sold regardless of mask (a sell needs only an open). "In `universe_membership`" is read literally: any row for the latest visible `month_end`, watchlist rows included. Disposition/changed_trading rows count if `available_at` is null or at or before the decision cutoff; null `end_date` is open-ended (blocks).
  7. *Rebalancing.* A book is a full target: absent names go to 0, positions are reset to the target weights at E (including trimming drift), and no rebalancing happens between books. Buys are scaled down together if cash (after sell proceeds, possibly blocked, and costs) cannot fund them. The spec does not say what happens to weights; they are fractions of NAV at the execution open.
  8. *Limit-down sell.* A day without a print does not consume one of the 5 attempts. A new book restarts the order set but keeps the attempt count for a name still being sold. Partial sells (trims) follow the same lock rule as full exits.
  9. *Suspensions.* A held name with no adjusted price on a day is carried flat; the gap return is booked when it trades again. A name with no open on the final day is closed at its last mark.
  10. *Daily cost placement.* Costs hit the fill day's return after the overnight move and before the intraday move. Gross returns add the day's costs back to the day's return (approximation, noted in the data dictionary).
  11. *Max drawdown* is reported as a number at most zero, with the peak starting at the initial NAV 1.0.
  12. *`as_of` does not serve `adjusted_prices`* (it embeds future corporate actions); raising `DataError` was my choice. Rows with null `available_at` are never served. `benchmark_index` is loaded but unused because the spec benchmarks 0050 from `adjusted_prices`.
  13. *Log path.* `run_backtest` has no log-path argument (a strategy could otherwise bypass the budget); `log.LOG_PATH` is a module constant that tests monkeypatch. The log is locked with `fcntl.flock` (Linux). Evaluation requires a 0050 row set in `adjusted_prices` (`DataError` otherwise, logged as an error line).
  14. *Hash.* `EVALUATOR_SHA256` covers `src/twdata/research/evaluator/*.py` only (not `research/__init__.py`, not tests), sorted by file name. The spec's phrase "the evaluator files" did not list them; any `.py` added to that directory changes the hash.
  15. The spec's file list for the Lead's `make_research_data.py` is not checked here; the loader trusts the column names in `schema.py` and fails with `KeyError` if a column is missing (not a friendlier `DataError`).
  16. `ruff format` is part of the freeze: the hash was generated after the final format.
- **What I would do differently next time:** have the spec define window names, turnover normalisation and the end-of-window rule before writing code; give the hash file format (hex digest, one line) explicitly.
