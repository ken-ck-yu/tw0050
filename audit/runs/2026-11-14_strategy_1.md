# Run report: strategy agent / H1 revenue drift (strategy_1)

- **Task and agent name:** strategy agent, hypothesis H1 (drift after monthly revenue surprises), early lane. Builds target books for the frozen evaluator. No real data, no network, no token.

  - `src/twdata/research/strategies/revenue_drift.py` (`build_books`, `diagnostics`, `run_h1(settings, window, out_dir=None)`, plus helpers `decision_dates`, `select_book`, `falsification`)

- **Result:** 33 strategy tests pass; the whole suite, `ruff check` and `ruff format` pass. `run_h1` was never run on real data.
- **Problems hit and how each was resolved:**
  - `ceil(0.10 * n)` in floating point is wrong at n = 30 (`0.1*30 = 3.0000000000000004` gives 4). I use integer arithmetic `-(-n*10 // 100)`; a test covers n = 30, 31, 101.
  - `RunRecord` has no `params` or `cycle` fields (only the hash). I add `params` and `cycle` to the JSON record explicitly.
  - Shell guard refused compound commands that mix git and heredocs; used the file tools instead.
- **Decisions (ambiguities resolved conservatively):**
  1. Decision dates: a month is skipped if the calendar has no trading day on or after the 10th within that month, if that day is after `end`, or if there is no later trading day to execute on (the evaluator would raise `BookError`). No book is created for such a month.
  2. Revenue month `m` = first day of the month before the decision month; `m-12` = same month of the previous year. Rows are matched on `event_date` exactly (first of month).
  3. If the visible table holds several rows for one (stock, month), the one with the latest `available_at` (visible at the cutoff) is used (restatement). A null revenue counts as missing.
  4. Eligibility needs year-ago revenue strictly greater than zero. Current revenue of zero or negative is allowed (gives yoy of -1 or lower, never selected unless n is tiny).
  5. Empty visible universe, or no eligible stock: an empty book (all cash) is still emitted, so the evaluator holds cash that month.
  6. Diagnostics: pair of consecutive books (b0, b1), from execution open of b0 to execution open of b1, adjusted opens. Selected names or universe stocks without both opens are skipped for that month; the universe is the b0 decision-date universe (benchmark excluded, not filtered to eligible stocks, not filtered by tradeability). Months where b0 is empty or no return is available are not counted (`n_months`). `avg_names` averages over all books, empty ones included. The last book has no successor and yields no pair. Extra keys `top_mean_gross_monthly` and `median_gross_monthly` are reported beside the required ones.
  7. Falsification: three conditions, each must pass or the card is falsified; a missing, NaN or non-finite number fails its condition. "Net mean excess return over 0050 above zero" is tested as both `excess_annual_return > 0` and the mean daily excess from `rec.daily > 0` (conservative: both). Net Sharpe must be at least 0.5 (below 0.5 falsifies). On the train window the verdict reads "not evaluated (train window ...)", the three conditions are still listed.
  8. `run_h1` accepts only `train` and `validation` (ValueError for `dev` or others) before loading data or touching the log, so a wrong argument cannot burn a budgeted run.
  9. `run_h1` makes exactly one `run_backtest` call. If it raises (budget, data), the exception propagates and no output files are written. The result dict has the keys `record`, `diagnostics`, `falsification`, `n_books`, `files`, `card_id`, `window`, `provisional`; the markdown file labels the result PROVISIONAL.
  10. `prices_raw` is visible to the strategy but unused; the spec lists no liquidity filter and the universe already is the liquid ranked set.
- **What in my instructions was missing, ambiguous or wrong:**
  - The spec says "net mean excess return over 0050" but not the unit (daily mean, annual compounded); I required both. If the author prefers one definition the verdict could change only when their signs differ.
  - The spec does not say whether the universe for the median should be restricted to eligible stocks or tradeable names; I used the full non-benchmark universe.
  - The card says "Score = yoy rank within the universe (percentile)" while the spec says Score = yoy; for a top-decile pick they select the same names (percentile rank is monotone), ties aside. The spec's tie rule is used.
  - The card says "if fewer than 10 names qualify, hold cash for the rest": with k = ceil(0.1 n) and weight min(1/k, 0.1), n < 10 gives one name at 10%, not an equal split of the whole book. Implemented as the spec says.
  - Both the card and the spec call the third falsification condition "gross monthly return"; it is measured open to open between consecutive books, not calendar months, and ignores names that cannot trade at the open (those are only dropped by the evaluator for the backtest).
  - The evaluator's `window_bounds` is not exported in `evaluator/__init__.py`; I import it from `twdata.research.evaluator.engine` rather than re-deriving window dates.
  - `research/runs/` does not exist in the repo; `run_h1` creates it on first write. It is not gitignored, so real outputs there would be committable (they contain no data series, only summary metrics).
- **What I would do differently next time:** ask the lead up front for the unit of the excess-return condition, and whether `window_bounds` may be imported from the evaluator's engine module.
